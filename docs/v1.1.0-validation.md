## Editing contract

Photo and video storage have independent automatic/custom editor state. New events
calculate when both count and individual size exist. Existing values initialize
linked only on exact integer equality; NULL and other custom totals remain unlinked.
Manual edits select custom, clearing custom stays unlimited, and the keyboard-accessible
**Use calculated maximum** restores linkage. Overall limits remain independent.
The API still receives explicit integer byte fields, with no persisted mode flag.

Tests cover missing/restored prerequisites, independence, overrides, redundant custom
totals, NULL, exact existing bytes and unrelated edits. Examples are exactly
500 × 25 MiB = 13,107,200,000 bytes and 20 × 500 MiB = 10,485,760,000 bytes.
BigInt multiplication checks the 1 PiB ceiling before Number conversion, including
the maximum accepted count × server file ceiling. No new dependencies, backend
behavior, API fields or migrations; schema still ends at 012.

## Browser and complete flows

Desktop and 390 × 844 mobile checks covered independent calculations, manual override,
custom NULL, Enter-based relinking, missing input/resumption, formula-equal initialization,
and unrelated saves. API readback confirmed exact 1,049/2,097-byte individual limits
and products with an independent 10,737-byte overall ceiling. Number fields retain
labels and hint references; mode is textual, keyboard focus visible, no disruptive
live announcements, and no horizontal overflow.

Local PNG/MP4/MOV uploads retained contributor names, typed counts and storage.
Photo preflight rejected an oversized image. A server photo-count failure displayed
the typed quota error; raising the quota and retrying sent only that failed file
(five ready files, no duplicates). Add-more retained the name. QR/public URL and
admin sections remained present; the closed event uses media/files terminology.

Direct S3 browser PNG/MP4/MOV uploads completed through PUTs on object origin :18090.
Each object showed HEAD and `bytes=0-511` verification. PhotoDrop authorizes/finalizes;
it does not proxy the media body. Mobile completion and closed-event pages had no
horizontal overflow. No presigned URLs/tokens are included in this record.

The browser created an Immich album before media, with automatic import enabled,
then uploaded PNG/MP4/MOV. Administration reported Album ready and 3/3 imported,
with the correct **Open in Immich** URL. The integration suite additionally covers
manual/failed retry, cancellation, coalesced bursts, abrupt restart, outages/revoked
credentials and preservation of independent Immich copies after PhotoDrop deletion.
Mixed local/historical S3 export and Immich original-download hashes passed.

Password-only, combined and OIDC-only pages were inspected. Combined SSO created a
local session, which survived restart into OIDC-only mode. Logout showed SSO only,
without a password form; sign-in worked again. Signed-provider tests cover code/PKCE,
issuer/signature/audience, allowlists, browser binding, replay and outage isolation.

## Focused correctness/security review

Server upload/auth/import code is unchanged. Reviewed bounded 512-byte Sniff and
EOF-aware BMFF handling, streaming local reservations, direct HEAD/prefix class
matching, transactional asset-row reservations, independent typed/overall/session
ceilings and atomic legacy NULL completion. Full regression/race tests cover these
paths; frontend calculation does not replace server enforcement.

OIDC retains one-time hashed state/nonce/browser binding, short-lived PKCE verifier,
strict issuer/signature/audience and explicit allowlists. No access/ID/refresh tokens
are persisted; existing sessions/health/uploads do not depend on the IdP. Turnstile
keeps strict production hostname/action checks; injected verification is test-only.
Immich credentials remain runtime-only, identity is preserved and existing remote
copies are never deleted by PhotoDrop. No new sensitive logging or credential
plumbing was introduced. This is focused regression review, not a formal audit.
